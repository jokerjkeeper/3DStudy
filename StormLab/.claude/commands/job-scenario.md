# 關卡與劇情量產

本次請求：$ARGUMENTS

主代理只負責盤點、派工、核對產物與記錄狀態。將每筆內容工作交給獨立的新 subagent。保持來源唯讀，使用目前環境允許寫入且與來源隔離的工作目錄。遵守所在專案的規格、格式與既有驗證工具。

## 盤點與排程

1. 從指令參數或同一輪請求取得來源目錄、批量和範圍。辨識 `level_id`、`story_id`、`quest_id`、共用規格和對應表。優先採用明確 ID 或來源對應關係，支援一對多及跨關卡承接。標記缺資料或配對不明的項目，繼續處理可確認的項目。
2. 保存可續跑的清單，至少記錄 `job_id`、關卡／劇情／任務 ID、相依項目、預期輸出、狀態、各階段嘗試次數及產物版本。共享同一關卡或劇情的組別重用同一份已自驗的產物，避免重複派工。
3. 從一個有明確配對的項目開始，確認兩個供應方可以派工並回收，隨後按可用並行量處理其餘項目。依賴相同可寫檔案的工作採單一寫入者或獨立 Git worktree／暫存目錄。共用的 Unity 場景、表格與事件配置以各自獨立的差異或匯入檔交付，留到整合工作區驗證。

## 派工與自驗

- **劇情**：每個劇情 job 交給一個全新 GPT Codex subagent。使用可明確指定 Codex 的派工工具，或啟動一次新的本機 `codex exec`。要求產出劇情、台詞、事件與任務前後狀態，並以實際檢查結果自驗角色設定、事件 ID、分支及劇情承接。
- **關卡設計**：每個關卡 job 交給一個全新 Claude Code subagent。使用 Claude Code 的獨立子代理，或啟動一次新的本機 `claude -p`。要求產出關卡佈局、地形／路線、出生點、障礙、事件點與勝敗條件，以及可用的 Unity 資料或規格。自驗可達性、觸發條件、資產引用與勝敗流程。
- 每個 subagent 只接收本筆工單、固定版共用規格、必要的直接相依資料與自己的輸出目錄。使用全新會話，不分叉主代理完整對話、不接續其他工單的會話。先確認真正執行該工作的 CLI／代理身份，登入或派工不可用時記為受阻並保留待辦，不改用另一個模型假冒。
- 請製作者回傳產物路徑、Git commit 或檔案雜湊、自驗結果、驗證證據與待解事項。將檢查結果記為通過、失敗或未驗證。缺失或失敗時保存原因，再交給同類的另一個全新 subagent 修正；只傳回該筆所需的版本與問題。服務配額或連線中斷時保存進度並將該工作標為可恢復。

## 融合評估與人工審核

1. 等整合組所需的關卡與劇情都交付且自驗通過，再派**第三個全新、未參與製作的唯讀 subagent**。只給它固定版規格、關卡與劇情產物、任務／事件配置和自驗證據。評估關卡與任務的配合、劇情是否能由玩家實際行為觸發、事件位置與順序、分支及勝敗條件、可達性與跨關承接。若專案有驗證入口，在隔離的整合工作區驗證同一版本。手工推斷與實跑證據分開記錄。
2. 評估報告附上判定、產物版本、檔案或事件 ID、重現條件、阻塞點與建議調整的一側。有阻塞點時，只把受影響產物交給原類別的全新製作 subagent 修正，再重跑該側自驗和所有受影響組別的融合評估。無法執行必要驗證時標記原因，維持待驗證狀態。
3. 評估通過後進入「待人工審核」。交付每組的關卡預覽／可測場景、劇情與任務預覽、驗收證據、核准所對應的精確產物版本及例外清單。保留續跑位置。收到使用者核准前不合併主分支或發佈。人工退回時沿用相同的修正與再驗流程。

預期狀態：待派工 → 製作中 → 自驗通過 → 融合評估 → 待人工審核。另行記錄待修正、待驗證與受阻。重跑時核對規格和產物版本，只重跑缺失或受影響的工作。
